## Steps
- Register datasources and test connectivity in `/admin/datasources`, then create `change_review` and `query_access` flows in `/admin/flows` and bind them to users via Permission Groups (`/admin/permission-groups`).
- Configure OpenAI-compatible AI Providers (connection, generation parameters, and reference pricing) in `/admin/review-engine/providers` and global daily AI Budgets in `/admin/review-engine/ai-budget`.
- Manage the 5 System Settings tabs under `/admin/settings` (`general`, `query`, `execution`, `branding`, `notifications`) and configure/test **LDAP (Singleton)** and **OIDC Providers** directly in **System Settings -> General (`/admin/settings/general`)** (or `/admin/identity-providers`); for high-impact changes, review the `Assess` impact dialog and confirm (`impact_token`).

## Detailed Guide
- **Datasources, Approval Flows, Permission Groups, Users & Identity Providers**:
  - **Datasources (`/admin/datasources`)**: Register MySQL (`mysql`, `tidb`, `oceanbase`, `polardb`) and PostgreSQL instances (`name`, `host`, `port` `1..65535`, and mandatory `version_constraint` such as `>=8.0,<9.0` which is never echoed on edit and must be re-typed on every save), configure at least one credential class (unified **Read-only (review & query)** entered once and synced to both `review` and `query` purposes with read-only sibling fallback, and **Execution (read-write)**; passwords and TLS PEM materials are encrypted at rest with AES-256-GCM and never echoed), and test connectivity.
  - **Approval Flows (`/admin/flows`)**:
    - **Change Flows (`change_review`) Prerequisites & Required Fields**: Before creating a change flow, you **must first create at least one Rule Set in `/admin/rule-sets`** (`Review Engine -> Rule sets`) and have at least one **enabled** Datasource in `/admin/datasources`. Every `change_review` flow requires a non-empty `name`, a bound `rule_set_id` (mandatory—saving without a Rule Set returns `1001 VALIDATION_FAILED`), and `1..N` serial stages (`position 1..N`) where each stage binds an **enabled** datasource (`enabled = true`), `1..10` approval steps (each with `>= 1` approver; any approve passes the step, any reject rejects the order), and `>= 1` execution actor. Multi-stage change flows must bind datasources of the same engine and compatibility mode.
    - **Query Flows (`query_access`)**: Require a non-empty `name`, `>= 1` enabled datasource (`can_query = true`, optional `can_export`), and `1..10` approval steps (no Rule Set or execution actors).
  - **Permission Groups (`/admin/permission-groups`) & Users (`/admin/users`)**: Assign users to permission groups and grant flows to each group. Create/disable users or reset passwords in `/admin/users` (`is_builtin_admin` cannot be disabled or deleted).
  - **Enterprise Identity Providers — LDAP & OIDC (`/admin/settings/general` and `/admin/identity-providers`)**:
    - **Where to Configure**: Embedded directly at the bottom of **System Settings -> General (`/admin/settings/general`)**, and also accessible via the standalone route `/admin/identity-providers`.
    - **LDAP Provider (Singleton — Only 1 LDAP Instance Allowed)**:
      - **Transport Security**: Supports **`ldaps`** (implicit TLS, typically port `636`) and **`starttls`** (typically port `389`) only. Plaintext LDAP and `insecure_skip_verify` are strictly forbidden; a valid **TLS Server Name (`server_name`)** matching the server certificate SAN is mandatory.
      - **Configuration Fields**: Display Name (`display_name`), Host (`host`), Port (`port`), Transport Security (`ldaps` / `starttls`), TLS Server Name (`server_name`), Service Bind DN (`bind_dn`), Bind Password (`secret`, write-only encrypted at rest with AES-256-GCM; leave blank when editing to keep the existing secret), Base DN (`base_dn`), User Filter (`user_filter`, must contain the `{username}` placeholder, e.g., `(&(objectClass=user)(sAMAccountName={username}))` for Active Directory or `(&(objectClass=inetOrgPerson)(uid={username}))` for OpenLDAP), Username Attribute (`username_attribute`, e.g., `sAMAccountName` or `uid`), Display Name Attribute (`display_name_attribute`, e.g., `displayName` or `cn`), Email Attribute (`email_attribute`, e.g., `mail`), and Enabled switch (`enabled`).
      - **LDAP Connection Test (`Test Connection`)**: Executes 4 real diagnostic stages (`tcp_connect` -> `tls_handshake` -> `service_bind` -> `base_dn_check`) and reports the outcome (`succeeded` or stage-specific failure).
    - **OIDC Providers (Multiple Instances Supported)**:
      - **Configuration Fields**: Provider Key (`provider_key`, immutable slug matching `^[a-z0-9][a-z0-9_-]{1,62}$`, e.g., `corp-oidc`), Display Name (`display_name`), HTTPS Issuer URL (`issuer_url`, must use `https://`), Client ID (`client_id`), Client Secret (`secret`, write-only encrypted at rest with AES-256-GCM), Scopes (`scopes`, space- or comma-separated and must include `openid`, e.g., `openid profile email`), Username Claim (`username_claim`, e.g., `preferred_username`), Display Name Claim (`display_name_claim`, e.g., `name`), Email Claim (`email_claim`, e.g., `email`), and Enabled switch (`enabled`).
      - **Server-Generated Callback URL & Security**: The OIDC Redirect/Callback URI is automatically generated by the backend as `<origin>/api/v4/auth/oidc/<provider_key>/callback` (using `general.public_base_url` when configured) and is not manually entered in the form. OIDC login enforces **Authorization Code + PKCE (`S256`)**, `state`, and `nonce` verification (`1009 OIDC_CALLBACK_INVALID` on mismatch).
      - **OIDC Connection Test (`Test Connection`)**: Executes 3 real diagnostic stages (`issuer_discovery` via `/.well-known/openid-configuration` -> `jwks_fetch` -> `endpoint_validation`).
    - **Login Page (`/login`) & Disabling Protection**: When enabled, OIDC providers render as top SSO buttons on `/login` (`Sign in with <Display Name>`), and LDAP renders as a `[Local Account | LDAP]` tab switcher at the top of the credential form. Disabling or deleting an enabled LDAP/OIDC provider uses two-step impact assessment (`Assess` -> `impact_token`, `1011`).
  - **System Announcements (`/admin/announcements`)**: Publish, schedule, or archive banner announcements displayed in `/workspace`.
- **AI Providers & Global Daily AI Budget (`/admin/review-engine/*`)**:
  - **AI Providers (`/admin/review-engine/providers` — 3 Form Sections)**:
    1. **Connection Configuration**: OpenAI-compatible model endpoint (`https://` is required for public internet targets; `http://` or `https://` is permitted for private RFC1918 LAN targets such as internal vLLM/Ollama servers and allowed loopback targets, with `addrguard` SSRF and DNS-rebinding protection enforced on every dial), model name, priority (`selection_priority`), and encrypted API key (`write-only`).
    2. **Generation Parameters**: Configure `reasoning_effort` (`low`, `medium`, `high`, or provider default), `max_tokens` (`256..200,000` or provider default), `temperature` (`0..2` or provider default), and optional `system_prompt_profile` (`default`, `san`, or omitted for automatic detection from normalized `model_name`: `xmodel`/`san`/`sql-audit-nano` `v1`/`v2`/`v3` names and tags such as `xmodel-v3.1`, `san-v3.1`, `SAN-4B-v3.1`, or `san:v3.1` resolve to `default` anonymized mode for transition vLLM/Ollama deployments, versionless `san` or `sql-audit-nano` models resolve to `san` local Raw-SQL Native mode with `>256`-character literal truncation and versionless minimal prompts, and all other models resolve to `default`). Modifying generation parameters, `system_prompt_profile`, or `model_name` updates the provider plan hash (`PrivacyContractHashDefault` vs `PrivacyContractHashSAN`) and invalidates unsubmitted precheck runs (`outdated`).
    3. **Reference Pricing (`CNY` / `USD` per 1M Tokens)**: Configure versioned, IANA timezone-aware daily time-of-day rate windows (`[start, end)`) across 4 price categories (regular input, output, cached read `cached_tokens`, cache write `cache_write_tokens`). All cost views carry the permanent disclaimer that reference cost calculation is for reference only and actual billing follows the AI provider's invoice.
  - **AI Budget (`/admin/review-engine/ai-budget`, redirected from `/admin/settings/ai-budget`)**:
    - Configures the **Global Daily AI Cost Budget** (`daily_budget_minor_units`, `currency`, `enforced`) and **Provider Cost Alert Threshold** (`provider_cost_alert_threshold_percent`). **No per-order token or cost budget exists anywhere on the platform (`R008` / `S006`)**.
    - Displays **Today's Usage Ring Chart** and **Reference Cost Statistics & Call Details** grouped by currency (`CNY` / `USD`). Toggling `enforced` requires two-step impact confirmation (`1011`).
- **All 5 System Settings Tabs (`/admin/settings/*`) & Two-Step High-Impact Confirmation (`1011`)**:
  1. **General (`/admin/settings/general`)**: User self-registration switch (`registration_enabled`), system timezone (`system_timezone` IANA picker), default locale (`default_locale`: `zh-CN` / `en-US`), `public_base_url` (used to generate "View Order" links in notifications and OIDC callback URLs), plus embedded **LDAP (Singleton)** and **OIDC Provider** SSO configuration and connection testing.
  2. **Query (`/admin/settings/query`)**: Query access approval switch (`approval_enabled`), default statement timeout (`default_timeout_ms`, default `30,000 ms`, range `1..300,000 ms`), maximum approved query access duration (`maximum_approved_access_duration_minutes`, range `1..525,600 minutes`), and maximum query result rows (`max_result_rows`, default `1,000`, range `1..100,000`).
  3. **Execution (`/admin/settings/execution`)**: Execution window restriction (`restriction_enabled`), allowed weekly execution time windows (`windows`: weekday multi-select + `start_local_time` -> `end_local_time`), and Online Schema Change (`osc.tool`: `none` or built-in in-process `gh-ost`—`pt-osc` is not supported—plus 18 `osc.defaults` parameters across load protection `max_load`, `critical_load`, `critical_load_interval_millis`, `critical_load_hibernate_seconds`; batching `chunk_size`, `dml_batch_size`, `max_lag`, `nice_ratio`; cut-over/retry `cut_over_lock_timeout_seconds`, `retries`, `heartbeat_interval_millis`, `exponential_backoff_max_interval`; and switches `exact_rowcount`, `concurrent_rowcount`, `ok_to_drop_table`, `timestamp_old_table`, `cut_over_exponential_backoff`, `attempt_instant_ddl`).
  4. **Branding (`/admin/settings/branding`)**: Platform title, logo, and branding customization.
  5. **Notifications (`/admin/settings/notifications`)**: Configure the 4 notification channel types (`email`, `dingtalk`, `feishu`, `slack`), notification rules, and delivery logs.
  - **Two-Step High-Impact Confirmation (`1011 PRECONDITION_REQUIRED`)**: Saving high-impact settings calls `Assess` first to display affected resources and submits the single-use `impact_token`.
